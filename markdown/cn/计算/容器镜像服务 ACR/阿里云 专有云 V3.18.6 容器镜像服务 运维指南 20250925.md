# 1.登录Apsara Uni-manager运维控制台

本文介绍运维工程师等相关用户如何登录到Apsara Uni-manager运维控制台。

**前提条件**

- 已从部署人员或管理员处获取Apsara Uni-manager运维控制台的访问地址、用户名和密码。

  Apsara Uni-manager运维控制台访问地址格式为*region-id*.ops.console.*intranet-domain-id*。

- 推荐使用Chrome浏览器。

**操作步骤**

1. 打开浏览器。

2. 在地址栏中，输入Apsara Uni-manager运维控制台的访问地址，按回车键。

   ![](assets/8687be861b518abf130a8b39086e180e.jpeg)

   > **说明**
   >
   > 您可以单击右上角的当前语言切换其它语言。当前支持简体中文、英文、繁体中文三种语言切换。

3. 输入正确的用户名及密码。

   > **说明**
   >
   > - 登录Apsara Uni-manager运维控制台的用户名和密码请从部署人员或管理员处获取。
   >
   > - 若连续输入密码错误三次，系统将启动图片验证码登录功能；若连续输入错误五次，账户将被锁定，请联系管理员进行激活。

   首次登录Apsara Uni-manager运维控制台时，需要修改登录用户名的密码，请按照提示完成密码修改。

   为提高安全性，密码必须满足以下要求：

   - 必须包含英文大小写字母。

   - 必须包含阿拉伯数字（0~9）。

   - 必须包含特殊符号，包括感叹号（!）、at（@）、井号（#）、美元符号（$）、百分号（%）等。

   - 密码长度为10~20个字符。

4. 单击**账号登录**。

# 2.管理组件

本文介绍组件的常用操作，包括查看组件监控信息，登录组件机器和重启组件机器。

**查看组件监控信息**

1. 登录Apsara Uni-manager运维控制台。

2. 在页面顶端选择**运维 > 服务运维**。

3. 在服务运维页面**模糊搜索**文本框中搜索acr，单击acr右侧**操作**列下的**管理**。

4. 在**详情**页面单击**服务实例**页签，单击**服务实例**下的服务名称。

5. 在**服务实例Dashboard**页面，**服务角色列表**区域，单击目标服务角色右侧**操作**列的**详情**。

6. 在**服务实例Dashboard**页面，您可以查看服务角色机器监控信息和服务角色监控信息。

**登录组件机器**

1. 登录Apsara Uni-manager运维控制台。

2. 在页面顶端选择**运维 > 服务运维**。

3. 在服务运维页面**模糊搜索**文本框中搜索acr，单击acr右侧**操作**列下的**管理**。

4. 在**详情**页面单击**服务实例**页签，单击**服务实例**下的服务名称。

5. 在**服务实例Dashboard**页面，**服务角色列表**区域，单击目标服务角色右侧**操作**列的**详情**。

6. 在**服务角色Dashboard**页面<strong>，机器信息</strong>区域，单击目标机器右侧**操作**列的**终端**。

**重启组件机器**

1. 登录Apsara Uni-manager运维控制台。

2. 在页面顶端选择**运维 > 服务运维**。

3. 在服务运维页面**模糊搜索**文本框中搜索acr，单击acr右侧**操作**列下的**管理**。

4. 在**详情**页面单击**服务实例**页签，单击**服务实例**下的服务名称。

5. 在**服务实例Dashboard**页面，**服务角色列表**区域，单击目标服务角色**操作**列的**详情**。

6. 在**服务角色Dashboard**页面，**机器信息**区域，单击目标机器**操作**列的**重启服务角色**。

7. 在弹出的对话框中单击**确认**。

# 3.组件功能

本文介绍容器镜像各个组件的功能。

**部署类组件**

此类组件不提供产品功能，但如果CrInit未到终态，需要先确认原因并解决。如果ServiceTests未到终态，可以检查产品功能类组件是否出现未到终态情况。

- CrInit：负责在产品部署时进行初始化工作，若该组件未到终态。可根据容器日志排查初始化过程中出现的问题，可能出现向POP注册OpenAPI 失败或其他问题，需要解决后再继续进行部署。

- ServiceTests：负责定期执行测试用例，检测产品功能是否符合预期。

**产品功能类组件**

此类组件提供产品功能，若出现产品功能不符合预期（如出现系统异常非业务异常），需要先检查组件是否到终态。

- CrRegistry：负责提供容器镜像推送拉取服务。

- CrAuthentication：负责提供认证服务。

- CrOpenapi：负责提供产品OpenAPI。

- CrManager：负责处理产品业务逻辑。

- CrSync：负责提供容器镜像同步服务。

# 4.组件运维

本文介绍组件的常用运维动作。

**部署类组件常用运维动作**

此类组件不需要在组件容器内进行运维，若出现未到终态情况，可以根据容器日志确认异常原因并进行运维动作。

- CrInit未到终态：登录组件所在机器，通过相关（例如 `docker ps` 和 `docker logs` ）命令定位并查询组件容器日志，根据容器日志中的异常信息确认问题，一般为外部依赖导致，解决问题后通过飞天基础运维平台控制台重启该组件。关于登录组件机器和重器组件机器的具体操作，请参见登录组件机器和重启组件机器。

- ServiceTests未到终态：查看组件监控信息，查询异常原因。如果异常为容器未正确退出，一般为测试用例未通过，请检查产品类组件是否正常。如果异常为其他，请确认是否由环境或其他问题导致。关于查看组件监控信息的具体操作，请参见查看组件监控信息。

**产品功能类组件常用运维动作**

此类组件需要在组件内容器内查询日志，若出现未到终态情况或有异常，可以根据容器日志确认异常原因并进行运维动作。

异常问题定位：

- 组件未到终态

  查看组件监控信息，查询异常原因。如果异常为容器健康检查失败，一般为飞天基础运维平台HTTPS证书未正确下发或外部依赖有问题。关于查看组件监控信息的具体操作，请参见查看组件监控信息。

- 组件到终态登录组件机器，进入容器内部查看日志（/alidata/www/logs/tengine）。关于登录组件机器具体操作，请参见登录组件机器。

  - 如果tengine目录内日志出现证书异常，一般为飞天基础运维平台HTTPS证书未正确下发。

  - 如果tengine目录内日志出现健康检查失败，一般为外部依赖有问题。

异常问题处理：

- 如果是HTTPS证书问题，常见于CrAuthentication和CrRegistry。应该检查集群配置，确认是否下发内容正确的证书。

- 如果是外部依赖产品问题，确认外部依赖是否到达终态。然后通过重启组件解决。关于重启组件机器的具体操作，请参见重启组件机器。

- 如果是其他异常，请确认是否由环境导致。
