# 1.登录Apsara Uni-manager运维控制台

本节介绍运维工程师等相关用户如何登录到Apsara Uni-manager运维控制台。

**前提条件**

- 已从部署人员或管理员处获取Apsara Uni-manager运维控制台的访问地址、用户名和密码。

  Apsara Uni-manager运维控制台访问地址格式为*region-id*.ops.console.*intranet-domain-id*。

- 推荐使用Chrome浏览器。

**操作步骤**

1. 打开浏览器。

2. 在地址栏中，输入Apsara Uni-manager运维控制台的访问地址，按回车键。

   ![](assets/8687be861b518abf130a8b39086e180e.jpeg)

   > **说明**
   >
   > 您可以单击右上角的当前语言切换其它语言。当前支持简体中文、英文、繁体中文三种语言切换。

3. 输入正确的用户名及密码。

   > 登录Apsara Uni-manager运维控制台的用户名和密码请从部署人员或管理员处获取。
   >
   > **说明**

   首次登录Apsara Uni-manager运维控制台时，需要修改登录用户名的密码，请按照提示完成密码修改。

   为提高安全性，密码必须满足以下要求：

   - 英文大小写字母

   - 阿拉伯数字（0~9）

   - 特殊符号，包括感叹号（！）、at（@）、井号（#）、美元符号（$）、百分号（%）等

   - 密码长度10~20个字符

4. 单击**登录**。

# 2.产品资源服务

<a id="section-2-1"></a>

## 2.1. 应用部署

所有弹性伸缩的业务逻辑层的应用都是无状态的，重启应用的方式都是docker restart。

- ess-init

  首先负责DB的初始化工作，完成之后会把弹性伸缩的所有API配置文件推送到POP配置中心，完成OpenAPI的初始化工作。

- trigger（依赖于ess-init）

  - 负责健康检查、最大最小检查、伸缩组删除清理等任务的执行。

  - 负责定时任务、报警任务的触发工作。

- coordinator

  对外提供服务的OpenAPI层，负责把请求持久化和任务下发。

- worker

  - 负责所有弹性任务的执行工作，包含ECS实例的创建、SLB后端服务器的添加、RDS白名单的添加、云监控分组的同步等。

  - 任务失败会自动重试、并设置有效的回滚机制。

- service-test

  负责整体应用运行状态的回归测试，包含60+回归用例，用于验证功能完备性。

<a id="section-2-2"></a>

## 2.2. 问题处理

本节介绍如何处理业务逻辑层相关的问题。

**操作步骤**

1. 前往阿里云业务支撑平台提交工单。

2. 在飞天基础运维平台上查看业务逻辑层依赖服务的状态。

   若服务无法执行，将对弹性伸缩业务逻辑层造成不同的影响，具体如下表所示。

   表 1. 服务与影响

   | 服务名称 | 主要影响 |
   | --- | --- |
   | middleWare.dubbo | 影响部署，服务不可用。 |
   | middleWare.tair | 影响部署，服务不可用。 |
   | middleWare.metaq（消息中间件） | 影响部署。 |
   | middleWare.zookeeper | 影响部署，服务不可用。 |
   | middleWare.jmenvDiamondVips | 影响部署，diamond配置项获取不到。 |
   | ram.ramService（主子账号） | 子账号服务不可用。 |
   | webapp.pop（API网关） | OpenAPI服务不可用。 |
   | ecs.yaochi（ECS控制系统） | 所有的创建ECS请求无效。 |
   | slb.yaochi（SLB控制系统） | 所有的关联SLB的请求失败。 |
   | rds.yaochi（RDS控制系统） | 所有的关联RDS的请求失败。 |
   | tianjimon（飞天基础运维平台） | 部分服务不可用。 |

# 3.巡检

<a id="section-3-1"></a>

## 3.1. 概述

弹性伸缩巡检主要为集群基础健康状况巡检。

集群基础健康状况巡检，主要包含以下两个方面：

- 监控巡检

- 基础软件包版本巡检

<a id="section-3-2"></a>

## 3.2. 监控巡检

主要包括基础监控和连通性监控巡检。

<a id="section-3-3"></a>

## 3.3. 基础软件包版本巡检

主要包括Trigger（任务管理系统）、Coordinator（OpenAPI系统）和Worker（任务处理系统）包版本校验，以及基础依赖包的版本校验等。
